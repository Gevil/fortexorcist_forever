## What a row's "sim VERIFIED" column does not claim

The suite drives `Comms` through its documented `readers` seam plus the real
event frame's `OnEvent` script (`test_warlock_group.lua`), so it proves the
**contract** — what a code, a lockdown answer, a prefix code or a nil verdict
does to our queue and counters. It does not prove the client answers the codes
this matrix names, that `addonChatRestrictionsForced` exists as a readable
CVar, that a real lockdown raises code 11, or that the throttle's real window
matches `BACKOFF_BASE`. Those are the F-comms 1–3 client columns, read on the
launch client per `docs/launch-day.md`.
